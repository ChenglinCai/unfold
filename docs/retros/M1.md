# Retro: M1, the walking skeleton

M1 made a two-segment episode on k-nearest neighbors, by hand, and wrote the economics files without rendering them. The episode lasts 102 seconds. Both segments render at low quality in under 20 seconds.

## What was hard

1. **Making the pictures match the words.** The narration says "four crosses and one circle answer" and "the island disappears". Random data broke those claims more than once. The fix was checks that fail the render, plus a search for data that passes them.
2. **Timing inside a beat.** A cue marks only the start of a beat. To show a caption at a particular phrase, the scene waited for a guessed fraction of the clip. That is fragile.
3. **The voice's pace.** The macOS voice speaks about 194 words per minute by default, which is too fast to follow. Its rate setting does not map evenly onto real speed, so finding a good pace took measurement.
4. **Bugs that only eyes could see.** Hollow circles turned solid, labels overlapped, and the error chart had the wrong shape. Each was found by looking at a contact sheet, which is a grid of frames from the video.
5. **An honest chart.** My first fix for the error curve drew held-out points from a different distribution than the training points. That would have made the chart look right for the wrong reason. Held-out data must come from the training distribution.
6. **A license surprise.** The plan named OpenStax Principles of Economics, but its 3rd edition forbids commercial use. The 2nd edition, under CC BY, has the same section and tables.
7. **YAML pitfalls.** A title with commas broke a one-line YAML mapping. A test caught it.
8. **A macOS trap.** macOS marked files in `.venv` as hidden, and Python then skipped the file that makes the package importable. The tests now add `src` to the path themselves.
9. **Test first slipped once.** I wrote the anchor module's tests alongside its code, not before it.

## What to automate first

| Lesson | Milestone | What to build |
|---|---|---|
| Contact sheets caught most bugs | M5 | A contact sheet after every render |
| Narration makes checkable claims | M4 | A claim check that runs before rendering |
| Cue timing inside a beat is a guess | M6 | Word-level timing from the voice or from Whisper |
| Formats drift and break | M4 | A schema for each format, with validation |
| Anchors must resolve | M2 | Anchor checks for every generated file |
| Sources need license checks | M2 | A license field that the tools require before use |

## Numbers

- 13 beats and 281 words of narration, spoken at about 165 words per minute.
- Four rounds of contact-sheet review before the episode looked right.
- Each low-quality render took between 8 and 19 seconds.
