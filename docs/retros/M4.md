# Retro: M4, text generation

M4 added a schema for every file format, `unfold check`, a build graph with saved results, and four generation steps. A canary guards each build, and a call log records each call. Six golden series built to storyboards with 42 calls, and every job passed on its first try. The first eval report found 9 failure types, and 7 binary checks now measure them.

## What was hard

1. **Tests that never ran.** pytest skips folders named build by default, so the full suite missed all 28 build tests. Only a count that failed to grow showed it.
2. **A folder that git ignored.** The ignore rule for Python build output also matched `src/unfold/build`.
3. **Test files that shared a name.** Two folders each held a `test_checks.py`, and pytest refused to load both. That happened twice.
4. **A swallowed canary.** The canary's error first subclassed the job error, so a job loop caught it and carried on. A broken runner must stop the build, so the canary error now stands alone.
5. **A batch that skipped work quietly.** macOS `xargs` dropped two of five builds with an error, yet the batch exited 0. A count of the call logs showed it.
6. **A wrong failure note.** Claude first called a velocity beat an invention. The source did mention banks and credit cards, in a block the segment never cited. Every failure note now gets checked against its source.
7. **Prompts that the model bends.** The plan prompt caps a series at 8 episodes, yet plans ran to 6 or 7 for short sources. Instructions alone do not hold a limit, and checks must.
8. **A usage limit.** The session stopped from 05:30 to 09:00, and auto-continue resumed it.

## Questions that wait for the maintainer

Two parts of principle II still wait for an answer. They are items 13 and 14 in `docs/progress.md`.

- Every new M4 step writes one file. The understand step still writes two, a knowledge map and study notes.
- Every key covers the prompt, the request, the model, and the schema. No key covers the manim or component-library versions, because no M4 output depends on them.

## What to automate first

| Lesson | Milestone | What to build |
|---|---|---|
| Plans run long and bury the core topic | next | Send the source's word count, and check the plan inside the build |
| Outlines ignore the plan's boundaries | next | Send only the episode's concepts to the outline step |
| Narration overshoots its target | next | Send the word target as a number, and check it inside the build |
| A batch can skip work quietly | now | Every batch counts what it started and what it finished |
| Paraphrase drift | later | A model check, after the code checks |
| Custom visuals dominate the storyboards | M5 | A component library ordered by what storyboards ask for |

## Numbers

- 42 model calls: 6 canaries and 36 generation jobs, with no retries.
- 300,652 input tokens and 99,116 output tokens, in about 18 minutes of model time.
- A second build of all six series: 0 calls, in 0.7 seconds.
- 7 binary checks, with pass rates from 33 to 92 percent. 40 of 82 beats cite no anchor, and the maintainer reviews them.
- 243 tests pass, 5 of them slow.
