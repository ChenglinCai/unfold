# Retro: M5, visuals

M5 added a theme, a grid of named regions, a layout check, five components, a scene step, and `unfold render` with contact sheets. All 12 golden segments render with no layout failures. The model writes data that tested code draws, so no model-written code runs.

## What was hard

1. **The checks passed, and the pictures were wrong.** The first renders passed every layout check. Yet the contact sheets showed invented data, overlapping labels, TeX as text, stage directions, and ghost frames. Looking at the sheets found all five.
2. **The model kept the letter of a rule.** Told to label example data, it labeled an invented poll "Example". A check on chart numbers now sends such charts to review.
3. **Feedback without a number stalled.** "Text size 15 is below 18" did not tell the model how much to cut. "Cut its text to about 60 percent" did.
4. **The runner checks schemas strictly.** It rejected two keywords that Pydantic writes, `discriminator` and `prefixItems`. Each rejection failed before any model call, so it cost no tokens.
5. **Parallel builds shared a cache.** Three processes raced on manim's text cache, and one scene got a file error as feedback.
6. **zsh again.** A loop over a variable ran one build with all names as one path, a slip from the first night.

## What to automate first

| Lesson | Milestone | What to build |
|---|---|---|
| Contact sheets catch what checks miss | M6 | A contact sheet for every episode, reviewed before release |
| Invented numbers look like facts | M6 | A model check that compares chart numbers with the source |
| Custom visuals still appear | later | Model-written manim code in a sandbox, with review |
| Feedback needs a number | now | Every check message says how far off the output is |

## Numbers

- 12 segments, about 51 seconds to render all of them at low quality.
- 24 scene jobs over two rounds. In the final round, 11 of 12 passed on the first try.
- 5 components and a custom card, 6 regions, and 56 visual tests, 1 of them slow.
